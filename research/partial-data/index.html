          THE DECISION, AND ITS COST
        

        

          Should product details survive an inventory failure?
        

        

          Nullable availability keeps the name and price available, but the
          client must represent unknown inventory. With Availability!, every
          non-null product has an availability value. In this schema, an
          inventory failure instead makes the whole product null—including
          details that were fetched successfully.
        

        

          Per-key errors keep the other keys useful when failures can be
          attributed to individual lookups. They cannot turn a failed
          database-wide request into trustworthy partial success. The error
          boundary has to match what the backend actually knows.
        

        

          All three schemas compose, the query validates against each, and every
          response is HTTP 200. A client library may still discard partial data
          according to its own error policy. This experiment observes the
          gateway response, not a client library's rendering behavior.
