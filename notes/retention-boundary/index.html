기본 복구 실험은 요청과 결과를 하나의 SQLite DB에 보관했습니다. 이번에는 요청과 확정 결과를 기록하는 로컬 프로세스, 처리 내역과 중복 방지 기록을 저장하는 수신 프로세스를 분리했습니다. 각자 SQLite DB를 갖고 HTTP로 통신하며, 두 DB를 묶는 트랜잭션은 없습니다. 아래에서 ‘효과’는 수신 측에 저장된 처리 한 건을 뜻합니다.

The base recovery experiment kept requests and outcomes in one SQLite database. Here, a local process records requests and their confirmed outcomes; a receiving process records completed operations and deduplication state. Each has its own SQLite database. They communicate over HTTP without a shared transaction. An “effect” is one operation recorded by the receiver.

01같은 관측, 다른 이력The same observations. Different histories.

기록된 두 실행을 비교해 보겠습니다. 첫 실행에서는 상대 시스템이 아무 효과도 저장하기 전에 연결을 끊습니다. 두 번째에서는 효과를 저장한 뒤 응답을 잃고, 나중에 키에 연결된 응답 기록을 삭제합니다. 이후 조회 결과는 둘 다 absent입니다.

오류 메시지만 비슷한 것이 아닙니다. 같은 요청과 같은 키를 사용한 두 실행의 로컬 HTTP 응답 본문과 전체 DB 테이블이 그대로 같습니다. 비교를 위해 식별자를 바꾸지도 않았습니다. 하지만 상대 기록의 효과는 한쪽이 0건, 다른 쪽이 1건입니다. 두 실행 모두 로컬에는 확인 번호가 남아 있지 않습니다.

Consider two recorded executions. In the first, the downstream owner closes the connection before committing anything. In the second, it commits an effect, loses the acknowledgement, and later prunes the retained response. A subsequent lookup returns absent in both executions.

This is stronger than two similar error messages. The same intent and key produce identical local HTTP response bodies and identical local database tables, without renaming identifiers. Yet the downstream journals contain zero effects in one execution and one in the other. The local owner has no receipt in either case.

감사기는 실행이 끝난 뒤 양쪽 기록을 읽어 차이를 구분할 수 있습니다. 재시도 정책은 같은 정보를 읽을 수 없습니다. 조회 API가 보여 주는 것은 보존된 중복 방지 상태이지, 과거의 모든 효과가 아닙니다. 감사기가 아는 사실을 정책도 조회할 수 있는 것처럼 그리면, 실제로는 없는 복구 수단을 만들어 낸 셈이 됩니다.

그래서 보호 정책은 재전송 기한 이후 요청을 미확정 상태로 남깁니다. absent를 실패로 바꾸거나, 키를 교체하거나, 조용히 다시 보내지 않습니다. 이 정책에서는 실제로 처리되지 않은 요청도 자동으로 해결할 수 없습니다. 효과가 0건이었던 실행에서도 요청이 미확정 상태로 남았습니다. 상태 이름은 needs-reconciliation입니다. 이 실험이 실제 운영자의 판단 절차까지 구현한 것은 아닙니다.

An auditor can distinguish them because it reads both journals after the processes stop. The retry policy cannot: its lookup exposes retained deduplication state, not an eternal history of effects. Showing the auditor’s knowledge as though it were available to the policy would make reconciliation look easier than it is.

The guarded policy therefore leaves the intent unresolved after its retry cutoff. It does not turn absent into failed, replace the key, or silently send again. That refusal has a cost. In the zero-effect execution, a legitimate request remains unresolved too. The state is called needs-reconciliation; this experiment does not implement an operator workflow that can resolve it.

02보낼 수 있는 시점과 도착하는 시점Permission to send is not an arrival guarantee.

로컬 시스템은 최초 전송 전에 첫 전송 시각, 알려진 최소 보존 기간, 가정한 시간 여유로 계산한 기한을 저장합니다. 논리 시각 10,020의 재시도는 기한 10,900 이전이므로 허용됩니다. 로컬에서 전송 기한을 지켜도, 상대 시스템에 도착하는 시점까지 제한할 수는 없습니다.

두 번째 비교에서는 HTTP 중계가 재시도 요청의 전달을 보류합니다. 부모 프로세스가 양쪽 실험 시계를 12,000으로 진행하고, 상대 시스템에서 만료된 키를 삭제합니다. 그 뒤에야 중계가 동일한 요청을 전달합니다. 수신자는 중복 방지 기록을 더 이상 갖고 있지 않으므로 효과를 새로 만들고 새 확인 번호를 돌려줍니다. 로컬 결과는 1건입니다. 상대 시스템의 효과는 2건입니다.

Before the first send, the local owner durably records a cutoff derived from its first-dispatch time, the known minimum retention, and an assumed timing margin. A retry at logical time 10,020 is permitted because the cutoff is 10,900. But permission to send is not a guarantee about when the receiver will accept it.

In the second decisive contrast, an actual HTTP relay holds that retry. The parent advances both fixture clocks to 12,000 and instructs the downstream owner to prune the expired key. Only then does the relay forward the same request. The receiver no longer has the deduplication record, so it creates another effect and returns a new receipt. The local owner records one grant. The downstream journal contains two effects.

재시도는 로컬 전송 기한 안에 보냈지만, 상대 시스템에서는 같은 키로 두 번째 처리가 일어났습니다. 여기의 숫자는 주입한 논리 시각이며 네트워크 지연 측정값이나 벤치마크가 아닙니다. 중계의 보류와 해제로 순서를 만들었고, 계산에 넣은 시간 여유가 실제 통신 지연을 감당한다고 검증한 것은 아닙니다. 이미 전송한 요청은 송신자의 기한이 지났다고 회수되지 않습니다.

The local cutoff was obeyed. The remote uniqueness property still failed. These numbers are injected logical clock values, not measured network delay or a benchmark. The relay controls the schedule; the configured margin establishes no real transit bound. A request already in flight is not revoked when its sender’s cutoff passes.

04기억의 경계를 설계에 드러내기Make the memory boundary explicit.

검사기는 이 경계를 따라 근거를 확인합니다. 상대 기록을 순서대로 재구성해 최소 보존 기간 이전의 삭제를 거절하고, 로컬 결과를 바로 그 시도에서 받은 확인 번호와 연결합니다. 같은 키로 발급된 과거 확인 번호가 있어도, 이번 시도의 결과라는 근거로 사용할 수는 없습니다. 로컬 1건의 기록이 내부적으로 일관돼도, 늦게 도착한 조건의 상대 효과는 2건이라고 명시합니다.

범위를 정한 가상 실행이며 실제 제공사 연동이나 exactly-once 증명이 아닙니다. 최소 보존 기간이 지났더라도 기록이 남아 있으면, 조회해서 기존 확인 번호를 복구할 수 있습니다. 기한이 지났다는 사실만으로 기록이 사라지지는 않습니다. 그러나 조회에서 기록을 찾지 못한 순간에는 키를 유지했는지만 물어서는 부족합니다. 효과를 만드는 시스템이 그 키를 구별할 기억을 아직 갖고 있는지까지 확인해야 합니다.

The checker follows the evidence across that boundary. It reconstructs retained records in journal order, refuses pruning before minimum retention, and binds the local grant to the positive receipt from that exact attempt. Merely finding some earlier receipt under the same key is insufficient. The recorded comparison explicitly marks the late-arrival case as two remote effects, even though one local grant is internally consistent.

These are bounded synthetic executions, not a provider integration or an exactly-once proof. A retained positive lookup can still recover a receipt after the minimum retention period; expiry alone does not erase a record. But once the record is absent, the right question is not just whether the key stayed the same. It is whether the effect owner still has the memory needed to make that key meaningful.

같은 키만으로는 부족합니다. 효과를 만드는 시스템이 그 키를 구별할 기록을 아직 갖고 있어야 합니다.The key is not enough. The effect owner must still retain the memory that makes it meaningful.

시계는 같은 속도와 기준점을 가정합니다. 응답 유실·보존 기한·중계 순서는 실험에서 주입했으며, 실제 서비스의 전송 상한이나 시계 신뢰를 입증하지 않습니다. 기록은 신뢰한 관측이며 해시는 실행 진위를 인증하지 않습니다.The clocks assume equal rate and zero offset. Lost acknowledgements, retention and relay scheduling are injected fixtures; they establish neither a real transit bound nor clock trust. Journals are trusted observations, and hashes do not authenticate execution.
