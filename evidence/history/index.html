이 기록을 읽기 전에

예약 완료 응답을 받은 뒤 조회했는데 “없음”이라고 나옵니다. 마지막 장부에 예약이 남아 있다는 사실만으로 이 응답을 설명할 수 있을까요?

이 개인 실험은 두 서버 프로세스와 SQLite에서 수집한 요청·응답 순서를 검사합니다. “장부”는 저장된 예약 상태입니다. 대조군은 실제 관측 중 조회 응답 한 건만 의도적으로 바꾼 기록이며, 실제 서버 장애를 재현한 결과가 아닙니다.

Before reading the capture

A reservation is confirmed, but a later lookup says it is absent. Can a correct final ledger explain what the caller saw?

This independent experiment checks request/response histories captured from two server processes and SQLite. The ledger is the stored reservation state. The control deliberately changes one recorded lookup response; it is not a reproduced server fault.
